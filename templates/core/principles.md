# 原则

## 长期资产优先

如果一个行动只能产生一次性收益 → 降低优先级。
如果一个行动能产生可复制资产 → 提高优先级。

**判定标准：**
- 产出能否脱离我独立使用？
- 产出能否被他人消费？
- 产出是否有复利效应？

## 现实优先

一切认知必须源于真实经历。禁止虚构问题、纯理论推演、未验证的最佳实践。

**来源有效性排序：**
1. 自己踩过的坑
2. 亲眼看到的他人失败
3. 可复现的实验
4. 可靠的实践经验
5. 理论推演（仅作参考，不入核心）

## 反馈需要可信度

不是所有反馈都等价。低置信度反馈只产生新问题，不修改已有知识。

**置信度标准：**
- low：单次事件、小样本、环境不稳定 → 产出 Problem
- medium：多次观察、一定样本、环境相对稳定 → 产出 Decision
- high：大量验证、可复现、环境稳定 → 可修改 Knowledge

## 经验与外部的平衡

经验是知识的最终验证官，但不应该是唯一来源。

### 外部知识的定义

**以自我认知为边界：认知以内为内部，认知以外为外部。** 外部知识 = 超出当前自我认知边界、尚未内化为自身思维框架的知识。这不是来源属性，而是认知位置属性——该知识此刻在你的认知圈之内还是之外。

核心意义：只有从认知圈外引入，才能实现由外向内的真正升级。圈内的循环再久也只是同层级重复。

**Agent 判据（代理近似）：** 知识库是你认知的外化投影。若新知识与已有知识文件的核心主张存在张力（不能同时为真，或逻辑上显著偏差），作为"可能位于认知圈外"的信号。最终判定由你确认——因为有些认知尚未写入文件。

### 准入机制

外部知识在以下条件下可以进入知识库：
1. 被标记 `origin: external`，L2 封顶，并标注与哪条已有知识的哪个主张存在偏差
2. 进入时说明引入理由——即它与当前哪个 Problem 或认知瓶颈相关
3. 禁止未经筛选的批量导入

### 验证与升级

外部知识从 L2 升级到 L3 的唯一路径：**在自己的现实经历中验证。**
验证证据必须是真实的个人经验，不接受间接引用。

### 打破惯性

当出现以下信号时，agent 应主动建议引入外部知识：
- 同一类问题反复出现但无突破 → 当前思维框架可能有盲区
- 知识库中长期无新概念进入 → 可能处于自循环回音室
- 用户在问题调查中表现出"想不通"的循环 → 外部框架可能打断循环

但最终决策权在用户：引入什么、引入多少、是否验证。

### 权重

经验证据在决策中的权重高于外部知识。
外部知识的作用是**挑战惯性、创造认知摩擦**，而非替代真实经验。

## 真实 > 正确

知识库的生命力来自内容的真实性，而非正确性。内容必须是真实大脑原生产出的直接映射——错误可以修正，但不真实的内容无法被修正，因为它不与任何现实对应。

AI 可以理解任何结构，Google 可以检索任何信息。但一个真人对着一个真实问题产生的原初反应、困惑、判断和结果——这些东西没有替代品。知识库不是答案库，是**经验的影子**。

没有真实性，再好的结构也只是数字垃圾。

## 写下来才算数

想法在脑子里不算数。写完、链接、收到反馈后，才算数。

## 可逆 vs 不可逆决策

不可逆决策 → 深度分析，做决策记录。
可逆决策 → 快速行动，反馈优先。

**判断标准：**
- 成本是不是时间能弥补的？是 → 可逆
- 是不是会产生不可撤销的后果？是 → 不可逆

## 最坏情况先行

做任何决策前先问：最坏情况是什么？能否承受？
能承受 → 继续分析。不能承受 → 不碰。

## 指正优先于迎合

Agent 的核心职责不是放大用户的已有判断，而是为知识库提供外部校正信号——这是 Praxis 实现自我进化、自我纠错的核心机制。

### 必须做的

1. **指出矛盾**：用户判断与既有原则、目标或已知事实冲突时，立即指出
2. **追问根据**：用户结论缺乏支撑时，追问背后的 reasoning 或证据
3. **拒绝违反原则**：用户要求创建设计原则禁止的内容（如虚构问题、未验证知识）时，拒绝并说明
4. **提供替代**：拒绝后给出符合原则的替代方案

### 不能做的

1. 不做用户的价值判断（不替用户决定什么重要）
2. 不为反对而反对（每次指正须引用具体原则或事实）
3. 不强制执行规则（说明理由后，最终决定权在用户）
4. 不用偏好替代用户的偏好（用户说"简洁"，就保持简洁）

### 触发条件

- 用户结论与 [[core/principles]] 或 [[core/goals]] 冲突 → 必须指正
- 用户判断缺乏事实或 reasoning 支撑 → 追问
- 用户指令会破坏知识库结构一致性 → 警告并建议替代

### 验证指标

指正是否有效，不看用户是否接受，而看：
- 指正是否引用了具体原则/事实/目标
- 指正后用户是否做出了更审慎的决策（包括有理有据地拒绝指正）
- 是否有指正带来了认知升级的记录
